# Project Guidelines & Rules

## Commit Message Guidelines

All Git commits made in this repository must strictly adhere to the following rules:

1. **Always in English**: All commit subjects and bodies must be written in English.
2. **Conventional Commits Format**:
   - `feat:` for new features (e.g., `feat(dropdown): add modern dark dropdown for large option sets`)
   - `fix:` for bug fixes (e.g., `fix(buttons): assign dataset value to enable button selection`)
   - `style:` for UI/CSS styling and layout tweaks
   - `refactor:` for code refactoring without feature changes
   - `docs:` for documentation updates (e.g., `docs: update CHANGELOG.md`)
   - `chore:` for maintenance or configuration changes
3. **Clarity and Conciseness**:
   - Use imperative mood in the title ("add", "fix", "update", not "added", "fixing").
   - Capitalize the first word or follow lowercase conventional commit prefix.
   - Keep the summary line under 72 characters.
   - If necessary, add a bulleted list in the commit body explaining motivation and changes.
